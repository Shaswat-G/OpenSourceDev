## Governance Models
Who sets the goal, vision, and direction of the project? Who decides what features to implement, what tasks to prioritize, which bugs to fix?

A project can still be open source without being open governance:
1. Even if only a select few can contribute
2. Even if decisions are made by an authority
3. Even if plans and discussion are not made public before release

the project is still open source.

Since OSS is only determined by the license, the governance model is a separate question.

### Company Led
S/W design, development and releases are controlled by one entity. External contributors may or may not be solicited. Plans and release dates may not be described openly. Examples include: Android, React, Vue, Angular, Swift, Rust, Go, RHEL, etc.

### Benevolent Dictatorship
One individual has overriding influence. Project quality and success depend heavily on dictator's wisdom and management capability. Maintainers write less and less code, and instead review and merge contributions from the community. Examples include: Linux, Python, Ruby, Perl, etc.

### Governing Board
A body (group) carries out discussion on open mailing lists and all decisions are made collectively. Examples FreeBSD, Debian, etc.


## Advantages of OSS
1. Collaborative Development: Ideas and code from developers all around the world leads to a better product. Having more eyeballs and testing can lead to better quality and security.
2. Faster Development: With more people working on the project, development can proceed faster.
3. Reduced Costs: No need to pay for licenses or development costs.
4. Competition for UI: This allows for more innovation and choice for users to choose from different implementations of the same software.
5. Transparency: Users can see the code and understand how it works, which can build trust.
6. Better code quality: People do not want to submit sloppy code. More reviewers and users can spot security bugs. 

## Successful OSS Projects:
1. Linux: Since 1991, it is the most widely used linux kernel in alsmost eveyrthing from phones, servers, smart devices, medical devices, fitbitts, etc. It is a benevolent dictatorship model with Linus Torvalds as the dictator.
2. Git: A VCS created by Linus Torvalds in 2005. It is a benevolent dictatorship model with Junio Hamano as the dictator.
3. Apache HTTP Server: Created in 1995, most widely used web server 50% of all websites. It is a governing board model with the Apache Software Foundation as the governing body.
4. Languages: Python, perl, ruby, go, rust, swift, etc. Many of these are benevolent dictatorships with a single dictator, Tex and Latex. 
5. GNU: gcc, gdb, glibc, bash, coreutils, etc. Many of these are benevolent dictatorships with a single dictator, Richard Stallman.
6. Databases: MySQL, PostgreSQL, MongoDB, etc. MySQL is a company led model with Oracle as the company. PostgreSQL is a benevolent dictatorship with a single dictator. MongoDB is a company led model with MongoDB Inc as the company.
7. Browsers: Firefox, Chromium, etc. Firefox is a company led model with Mozilla
8. Desktop env: GNOME, KDE, XFCE
9. Kubernetes: Created by Google in 2014, it is a container orchestration system. It is a company led model with Google as the company.
10. OpenStack: Created by Rackspace in 2010, it is a cloud computing platform. It is a company led model with Rackspace as the company.
11. OpenCV: Created in 1999, it is a computer vision library. It is a company led model with Intel as the company.
12. TensorFlow: Created by Google in 2015, it is a machine learning library. It is a company led model with Google as the company.
13. PyTorch: Created by Facebook in 2016, it is a machine learning library. It is a company led model with Facebook as the company.,
